# Bend spike (2026-10-26): not shipped, not in CI

Question: could Bend (bend-lang.com, v2.0.39) prove our core colour laws?

Model, simplified: 11 grey lightness levels (OKLab L = 0, 0.1, …, 1). The AA table is generated by `gen.py` from the real WCAG luminance ratio (achromatic OKLab: Y = L³). `ensure_contrast` keeps the text, or falls back to black or white. `derive_palette` puts the page at white in light mode.

Laws (`LAWS.bend`):
- `aa_always`: for every text and every background, `ensure_contrast(t, bg)` passes AA on bg.
- `page_white`: in light mode the page is white, for any brand colour.
- `palette_aa`: the palette's text passes AA on its page, in either mode.

Run it: `python3 gen.py && bend PROOF.bend`. It prints `ALL PROOFS CHECK` in about 0.15 s. The proofs are exhaustive case splits, 121 + 22 cases, each closed by `{==}`.

Mutation check:
- making `ensure_contrast` return the text unchanged fails `aa_always` at (L0, L0);
- a light page at L9 fails `page_white`.

`--verdict` (the Lean-checked kernel) needs Lean 4.34, which is not installed, so that was not run.

Verdict: see the v1 report. In short, this works for finite or discretized models. Our real code uses floating-point OKLCH and a solver, and proving that is out of reach: Bend has no proofs over F32. It would also mean keeping a second implementation in step with the TypeScript one. The 10k-palette property test stays the gate for the real code.
